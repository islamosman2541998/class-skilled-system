# نظام إدارة أعمال كلاس سكيلد للمقاولات العامة — وثيقة المتطلبات والتصميم

- التاريخ: 2026-11-12
- الحالة: مسودة للمراجعة
- المستخدمون: موظفو الشركة (إدارة، مبيعات، مهندسون، محاسبة). لا يوجد دخول لعملاء الشركة.

---

## 1. الهدف

نظام واحد يدير دورة العمل كاملة من طلب العميل حتى التسليم والضمان، وكل شيء فيه مربوط بالمشروع:

طلب ← معاينة ← عرض سعر ← عقد ومشروع ← تنفيذ ← فواتير وتحصيل ← تسليم وضمان

معايير النجاح:

1. أي موظف ينجز مهمته اليومية من شاشة واحدة وبأقل عدد من الخطوات.
2. الإدارة تعرف في أي لحظة: موقف كل مشروع، ربحيته، والمبالغ المستحقة والمتأخرة.
3. كل قائمة فيها بحث وفلاتر ونطاق تاريخ وتصدير Excel.
4. لا توجد قيمة ثابتة في الكود يحتاج المستخدم لتغييرها؛ كل شيء من الإعدادات.
5. الصفحات تفتح بسرعة على استضافة مشتركة عادية وعلى الموبايل.

## 2. خارج النطاق

- محاسبة عامة بقيود يومية وشجرة حسابات.
- الرواتب.
- المخزن وحركة الأصناف.
- بوابة دخول لعملاء الشركة.
- متابعة انتهاء المستندات (رخصة، إقامات، تأمين).
- تطبيق موبايل مستقل. النظام يعمل من متصفح الموبايل.
- إشعارات بريد إلكتروني أو SMS. الإشعارات داخل النظام فقط.

## 3. القرارات المعمارية

### 3.1 مشروع مستقل عن الموقع

الموقع الحالي `class-skilled` مبني بـ Tailwind و Livewire كامل. النظام المطلوب بتقنيات مختلفة (Bootstrap و jQuery و MVC)، لذلك يُبنى كمشروع Laravel مستقل بقاعدة بيانات مستقلة.

- المسار المحلي: `C:\laragon\www\class-skilled-system`
- الرابط المحلي: `http://class-skilled-system.test`
- قاعدة البيانات: `class_skilled_system` بترميز `utf8mb4_unicode_ci`
- الإنتاج: نطاق فرعي، مثل `system.class-skilled.com`

الربط مع الموقع عبر API فقط (القسم 10).

### 3.2 قيود الاستضافة

الموقع الحالي مصمم لاستضافة مشتركة بدون cron وبدون queue worker. النظام يُبنى على نفس الافتراض:

- `QUEUE_CONNECTION=sync`، والأعمال الثقيلة تُنفذ بعد إرسال الرد (`afterResponse`).
- لا يعتمد على cron. المهام الدورية تُنفذ عند أول طلب بعد موعدها مع قفل يمنع التكرار. لو توفر cron يُضاف سطر واحد ويعمل تلقائيًا.
- معالجة الصور بـ GD فقط. لا FFmpeg ولا تحويل فيديو على الخادم.
- الأصول تُبنى محليًا بـ Vite ويُرفع مجلد `public/build`.

### 3.3 التقنيات

الخادم:

| الغرض | الأداة |
|---|---|
| الإطار | Laravel 12 أو أحدث إصدار مستقر يعمل على PHP 8.3، بنمط MVC |
| قاعدة البيانات | MySQL 8 |
| الجداول | Livewire 4 (للجداول فقط) |
| الصلاحيات | spatie/laravel-permission |
| سجل النشاط | spatie/laravel-activitylog |
| المرفقات | spatie/laravel-medialibrary + intervention/image (GD) |
| الإعدادات | spatie/laravel-settings |
| ترجمة نصوص الواجهة من لوحة التحكم | spatie/laravel-translation-loader |
| تصدير Excel | spatie/simple-excel (تصدير متدفق لا يستهلك الذاكرة) |
| PDF | mPDF (يدعم العربية والاتجاهين بدون أدوات على الخادم) |
| الاختبارات والجودة | Pest، Pint، Larastan |

الواجهة:

| الغرض | الأداة |
|---|---|
| الهيكل والتنسيق | HTML، CSS، Bootstrap 5.3 (نسخة RTL و LTR) مخصصة بـ Sass |
| التفاعل | JavaScript و jQuery |
| الإشعارات السريعة | Toastr |
| التأكيد والتحذير | SweetAlert2 |
| رفع الملفات | FilePond |
| التاريخ ونطاق التاريخ | flatpickr مع اللغة العربية |

إضافة أي مكتبة أخرى تحتاج موافقة مسبقة.

### 3.4 تقسيم الكود

- المتحكمات (Controllers) رفيعة: تستقبل الطلب، تتحقق عبر Form Request، وتستدعي Action.
- منطق العمل في `app/Actions` و `app/Services` (حساب الإجماليات، الترقيم، تحويل عرض إلى مشروع، ربحية المشروع).
- الحالات الثابتة منطقيًا (حالة عرض السعر، حالة الفاتورة) في Enums. القوائم التي يديرها المستخدم (أنواع الخدمات، بنود المصروفات) في جداول.
- كل جدول عرض مكوّن Livewire يرث من مكوّن أساسي واحد `DataTable` (القسم 5.1).
- كل وحدة لها: Model، Policy، Controller، Form Requests، مكوّن جدول، واجهات Blade، اختبارات.

## 4. التصميم وتجربة الاستخدام

### 4.1 الاتجاه البصري

واجهة عمل هادئة وكثيفة المعلومات، متناسقة مع هوية الشركة ولوحة تحكم الموقع الحالية. لا تُستخدم قوالب لوحات تحكم جاهزة؛ التنسيق مبني على Bootstrap ومخصص بمتغيرات Sass.

الألوان الافتراضية (قابلة للتغيير من الإعدادات، وتُخرج كمتغيرات CSS):

| الاسم | القيمة | الاستخدام |
|---|---|---|
| كحلي | `#2B4168` | العناوين والعناصر الأساسية |
| كحلي داكن | `#0C122B` | القائمة الجانبية |
| سماوي | `#4FC3EE` | الإجراء الأساسي والعنصر النشط |
| نص | `#24324D` | النص الأساسي |
| نص ثانوي | `#5D6A80` | الوصف والبيانات الثانوية |
| حد | `#E3E8EF` | الحدود والفواصل |
| خلفية | `#F5F7FA` | خلفية منطقة المحتوى |

ألوان الحالات (نجاح، تحذير، خطر، معلومة) ثابتة الدلالة في كل النظام.

### 4.2 قواعد ملزمة

- لا رموز تعبيرية في أي مكان.
- لا تدرجات لونية، لا توهج، لا ظلال ثقيلة، لا أيقونات للزينة.
- الأيقونات وظيفية فقط ومن مجموعة واحدة بخط رفيع (Tabler Icons).
- النصوص تسميات مباشرة: اسم أو فعل. لا جمل ترحيبية، لا عبارات تسويقية، لا علامات تعجب.
- الرسائل قصيرة ومحددة: «تم الحفظ»، «لا توجد نتائج»، «تعذر الحذف: العميل مرتبط بمشاريع».
- حجم النص الأساسي 14 إلى 15 بكسل. العناوين لا تتجاوز 22 بكسل.
- الأرقام والهواتف والمبالغ بالأرقام الغربية (0-9) في اللغتين، ومحاذاة المبالغ في عمود واحد.
- المسافات والحواف موحدة: حافة 8 بكسل للحقول والأزرار، 10 للألواح.

### 4.3 الهيكل العام

- قائمة جانبية في جهة البداية (يمين في العربية، يسار في الإنجليزية)، مجموعات قابلة للطي، وتُطوى إلى أيقونات.
- شريط علوي: بحث شامل، زر «إضافة سريعة»، تبديل اللغة، الإشعارات، قائمة المستخدم.
- منطقة المحتوى: عنوان الصفحة، مسار التنقل، أزرار الإجراء في جهة النهاية.
- صفحة السجل (عميل، مشروع، عرض): ملخص ثابت أعلى الصفحة وتبويبات تحته.
- الاتجاه بخصائص منطقية فقط (`ms-`، `me-`، `text-start`) حتى ينقلب التصميم تلقائيًا.

### 4.4 الموبايل

- كل الشاشات تعمل من 360 بكسل بدون تمرير أفقي للصفحة.
- الجداول على الموبايل تتحول إلى بطاقات بأهم الحقول.
- شاشات المهندس (تقرير يومي، معاينة، مصروف، رفع صور) مصممة للموبايل أولًا: حقول كبيرة، كاميرا مباشرة، وأزرار في أسفل الشاشة.

### 4.5 الخطوط

- Cairo و Tajawal مستضافان محليًا.
- إعداد «الخط الأساسي» يحدد خط الواجهة كاملة. إعداد «خط العناوين» اختياري: نفس الأساسي أو الخط الآخر.
- يُحمَّل فقط الخط المستخدم فعليًا.
- نفس الاختيار يُطبق على ملفات PDF.

### 4.6 اعتماد التصميم قبل البناء

قبل بناء الوحدات تُنفذ شاشات مرجعية وتُعتمد: الهيكل العام، جدول قياسي، نموذج إدخال، صفحة مشروع، عرض الموبايل، قالب PDF لعرض السعر. بعد الاعتماد تُبنى كل الوحدات على نفس المكوّنات.

## 5. المعايير المشتركة

### 5.1 الجدول القياسي (كل قائمة في النظام)

مكوّن Livewire أساسي واحد تُبنى عليه كل الجداول، ويوفر:

- بحث نصي في الحقول المهمة لكل وحدة، مع تأخير 300 مللي ثانية.
- فلاتر لكل عمود قابل للتصنيف: قائمة، قائمة متعددة، نعم/لا، نطاق مبلغ.
- نطاق تاريخ «من – إلى» على التاريخ الرئيسي للسجل، مع اختصارات: اليوم، هذا الأسبوع، هذا الشهر، الشهر الماضي، هذه السنة.
- شريط يعرض الفلاتر المفعّلة مع إزالة كل فلتر منفردًا وزر «مسح الفلاتر».
- ترتيب بالنقر على رأس العمود.
- ترقيم صفحات من الخادم مع اختيار عدد الصفوف (15، 25، 50، 100).
- إظهار وإخفاء الأعمدة، ويُحفظ اختيار كل مستخدم.
- حفظ مجموعة فلاتر باسم واستدعاؤها لاحقًا (لكل مستخدم).
- حالة الجدول في رابط الصفحة حتى يمكن مشاركة الرابط والرجوع إليه.
- تصدير Excel للنتيجة المفلترة بالأعمدة الظاهرة.
- تحديد صفوف وإجراءات جماعية: حذف المحدد، تصدير المحدد، وإجراءات خاصة بالوحدة.
- «حذف الكل»: يحذف كل ما يطابق الفلتر الحالي، لا الصفحة الحالية فقط، بعد تأكيد يعرض العدد.
- صف إجمالي للأعمدة المالية يحسب كامل النتيجة المفلترة.
- تبويب «المحذوفات» لمن يملك الصلاحية.
- حالة فارغة واضحة مع زر الإضافة.

### 5.2 الحذف وسلة المحذوفات

- كل حذف هو حذف مؤقت (Soft Delete) وينتقل للسلة.
- من السلة: استرجاع، أو حذف نهائي بصلاحية خاصة.
- كل حذف يسبقه تأكيد SweetAlert2. الحذف النهائي وحذف الكل بتأكيد إضافي.
- السجل المرتبط بسجلات أخرى (عميل له مشاريع، مشروع له فواتير) لا يُحذف، وتظهر رسالة بالسبب. في الحذف الجماعي يُحذف المسموح ويُعرض عدد المتخطى.
- المستندات المالية بعد إصدارها (فاتورة، سند قبض، مستخلص معتمد) لا تُحذف. تُلغى بسبب مكتوب وتبقى ظاهرة بحالة «ملغاة» ولا تدخل في الإجماليات.
- مدة الاحتفاظ بالسلة إعداد (افتراضيًا بدون حذف تلقائي).

### 5.3 النماذج

- إرسال عادي عبر Controller و Form Request. أخطاء التحقق تظهر تحت الحقل، والنجاح بإشعار Toastr.
- الإضافة السريعة لسجل مرتبط (عميل جديد أثناء إنشاء عرض سعر) في نافذة منبثقة عبر AJAX دون مغادرة النموذج.
- الحقول الإلزامية مميزة. القيم الافتراضية تأتي من الإعدادات.
- تحذير عند مغادرة نموذج فيه تعديلات غير محفوظة.
- النماذج الطويلة مقسمة أقسامًا، وزر الحفظ ثابت أسفل الشاشة.
- منع الإرسال المزدوج بتعطيل الزر أثناء الحفظ.

### 5.4 رفع الصور والفيديو والملفات

مكوّن رفع واحد يُستخدم في كل النظام (FilePond):

- سحب وإفلات، اختيار متعدد، لصق من الحافظة، وكاميرا مباشرة على الموبايل.
- الصور تُصغَّر وتُضغط في المتصفح قبل الرفع (أقصى بُعد 2000 بكسل)، فيكون الرفع سريعًا من الموقع.
- الملفات الكبيرة تُرفع مقطعة (Chunks) مع استكمال تلقائي عند انقطاع الاتصال، فلا تتأثر بحدود PHP على الاستضافة.
- شريط تقدم لكل ملف، مع إلغاء وإعادة محاولة.
- الخادم ينشئ صورة مصغرة WebP للعرض في القوائم.
- الفيديو يُحفظ كما هو (MP4 أو WebM). صورة الغلاف تُلتقط في المتصفح وتُرفع معه.
- الأنواع المسموحة والحجم الأقصى لكل نوع من الإعدادات. التحقق من النوع في المتصفح والخادم.
- الملفات على قرص خاص، ولا تُعرض إلا لمستخدم له صلاحية على السجل.
- عرض المرفقات: شبكة صور بمعاينة مكبرة، مشغل فيديو، ومعاينة PDF داخل الصفحة.
- لكل مرفق: عنوان، تصنيف، من رفعه، ومتى. المرفقات قابلة للبحث والفلترة داخل السجل.

### 5.5 الإشعارات داخل النظام

- أيقونة في الشريط العلوي بعدد غير المقروء، وصفحة كاملة للإشعارات بفلاتر.
- كل إشعار يفتح السجل المعني.
- الأنواع وأيام التنبيه ومن يستلم كل نوع من الإعدادات.

| الحدث | المستلم الافتراضي |
|---|---|
| طلب جديد من الموقع | المبيعات |
| إسناد طلب أو معاينة أو مشروع أو صيانة لمستخدم | المستخدم |
| معاينة موعدها اليوم | المهندس المسؤول |
| عرض سعر بدون رد بعد عدد أيام | منشئ العرض |
| عرض سعر ينتهي خلال عدد أيام | منشئ العرض |
| دفعة تستحق خلال عدد أيام، أو متأخرة | المحاسبة والإدارة |
| فاتورة تجاوزت تاريخ الاستحقاق | المحاسبة والإدارة |
| مرحلة تجاوزت تاريخها المخطط | مدير المشروع والإدارة |
| مشروع يقترب من تاريخ الانتهاء | مدير المشروع |
| ضمان ينتهي خلال عدد أيام | الإدارة |

الإشعارات الزمنية تُولَّد بفحص دوري يعمل مرة كل ساعة عند أول طلب، دون cron، ولا تتكرر لنفس السجل.

### 5.6 البحث الشامل

حقل في الشريط العلوي (اختصار `Ctrl+K`) يبحث في: العملاء، الطلبات، عروض الأسعار، المشاريع، الفواتير، سندات القبض، بالاسم أو الرقم أو الهاتف. النتائج مجمعة حسب النوع ومقيدة بصلاحيات المستخدم.

### 5.7 سجل النشاط

- يُسجَّل: الإضافة، التعديل (القيمة قبل وبعد)، الحذف، الاسترجاع، تغيير الحالة، الطباعة، التصدير، تسجيل الدخول.
- يظهر كتبويب في صفحة كل سجل، وكشاشة عامة بفلاتر: المستخدم، الوحدة، نوع الإجراء، نطاق التاريخ.
- السجل للقراءة فقط.

### 5.8 اللغتان

- عربي (افتراضي، RTL) وإنجليزي (LTR). التبديل من الشريط العلوي ويُحفظ لكل مستخدم.
- نصوص الواجهة في ملفات اللغة وقابلة للتعديل من شاشة «الترجمة» في الإعدادات.
- بيانات القوائم (الخدمات، المراحل، بنود المصروفات، بنود الأسعار) تُدخل باللغتين في عمودين `_ar` و `_en`. العربي إلزامي والإنجليزي اختياري ويُعرض العربي عند غيابه.
- أسماء العملاء وعناوين المشاريع: حقل عربي إلزامي وحقل إنجليزي اختياري.
- المستندات المطبوعة تصدر بالعربية أو الإنجليزية أو باللغتين حسب اختيار المستخدم عند الطباعة.
- رسائل التحقق والإشعارات باللغتين.

### 5.9 الترقيم والعملة والضريبة

- لكل نوع مستند تسلسل مستقل: بادئة، عدد خانات، الرقم التالي، وإعادة التصفير سنويًا أو لا. كلها من الإعدادات.
- الرقم يُحجز عند الإصدار داخل معاملة قاعدة بيانات تمنع التكرار.
- العملة والخانات العشرية ونسبة الضريبة من الإعدادات (الافتراضي: درهم، خانتان، 5%).
- نسبة الضريبة تُحفظ داخل كل مستند وقت إنشائه، فلا يتأثر القديم بتغيير الإعداد.
- المبالغ تُخزن كأرقام عشرية دقيقة (`decimal`)، والحساب في الخادم.

### 5.10 الطباعة و PDF

- عرض السعر، الفاتورة الضريبية، سند القبض، المستخلص، محضر التسليم.
- ترويسة وتذييل من الإعدادات: الشعار، بيانات الشركة، الرقم الضريبي، البيانات البنكية، الختم والتوقيع.
- نصوص الشروط والأحكام من قوالب في الإعدادات وقابلة للتعديل داخل كل مستند.
- زر «إرسال واتساب» يفتح محادثة العميل برسالة من قالب قابل للتعديل ومعها رابط موقّع للملف ينتهي بعد مدة من الإعدادات.

## 6. المستخدمون والصلاحيات

- لا يوجد تسجيل ذاتي. المدير ينشئ المستخدمين.
- دخول بالبريد وكلمة المرور، مع «تذكرني» وتحديد لعدد المحاولات.
- المستخدم يغيّر كلمته ولغته. المدير يعيد تعيين كلمة أي مستخدم ويوقف حسابه.
- أدوار افتراضية قابلة للتعديل والإضافة: مدير النظام، الإدارة، مبيعات، مهندس مشروع، محاسب.
- صلاحيات لكل وحدة: عرض، إضافة، تعديل، حذف، استرجاع، حذف نهائي، تصدير، طباعة.
- صلاحيات خاصة: اعتماد عرض السعر، إلغاء مستند مالي، رؤية المبالغ والتكاليف، رؤية الربحية، إدارة الإعدادات، رؤية سجل النشاط.
- نطاق الرؤية لكل دور: «كل السجلات» أو «المسندة له فقط». المهندس افتراضيًا يرى مشاريعه فقط.
- عناصر القائمة والأزرار تختفي عند غياب الصلاحية، والتحقق يتم أيضًا في الخادم عبر Policies.

## 8. الوحدات

لكل وحدة: جدول قياسي (5.1)، مرفقات (5.4)، وسجل نشاط (5.7). المذكور هنا ما يخص كل وحدة.

### 8.1 العملاء

- الحقول: النوع (فرد أو شركة)، الاسم باللغتين، الهاتف، هاتف إضافي، واتساب، البريد، الرقم الضريبي، الإمارة والمنطقة، العنوان، المصدر، ملاحظات.
- للشركات: جهات اتصال متعددة (الاسم، الصفة، الهاتف).
- تنبيه عند تكرار رقم الهاتف.
- صفحة العميل: ملخص (عدد المشاريع، إجمالي التعاقدات، المحصل، المستحق) وتبويبات: الطلبات، المعاينات، العروض، المشاريع، الفواتير، المقبوضات، المرفقات، النشاط.
- البحث: الاسم، الهاتف، البريد، الرقم الضريبي. الفلاتر: النوع، المصدر، الإمارة، له رصيد مستحق، تاريخ الإضافة.

### 8.2 الطلبات

- الحقول: الرقم، العميل (أو بيانات جهة اتصال جديدة)، الخدمة، نوع المنشأة، حالة المشروع، الإمارة والمنطقة، المساحة، موعد البدء المتوقع، الوصف، المصدر، الحالة، المسؤول، تاريخ المتابعة، سبب الرفض.
- الحالات من الإعدادات. الافتراضي: جديد، تم التواصل، معاينة، عرض سعر، تم التعاقد، مرفوض.
- سجل متابعات داخل الطلب: مكالمة، رسالة، ملاحظة، مع التاريخ وصاحبها.
- الإجراءات: إسناد، تحديد موعد متابعة، حجز معاينة، إنشاء عرض سعر، إغلاق كمرفوض بسبب.
- عند أول تحويل يُنشأ العميل من بيانات الطلب تلقائيًا إن لم يكن موجودًا.
- البحث: الرقم، الاسم، الهاتف. الفلاتر: الحالة، الخدمة، المصدر، المسؤول، الإمارة، متابعة متأخرة، تاريخ الطلب.

### 8.3 المعاينات

- الحقول: الطلب أو العميل، التاريخ والوقت، المهندس، العنوان ورابط الخريطة، الحالة (مجدولة، تمت، ملغاة)، الملاحظات، القياسات، صور وفيديو.
- شاشة المهندس على الموبايل: معايناتي اليوم والقادمة، وتسجيل النتيجة والصور من الموقع.
- الفلاتر: الحالة، المهندس، الخدمة، تاريخ المعاينة.

### 8.4 بنود الأسعار

- قائمة بنود جاهزة: الخدمة، الوصف باللغتين، الوحدة، السعر الافتراضي، مفعّل.
- تُستدعى داخل عرض السعر بالبحث، وتبقى قابلة للتعديل داخل العرض.
- استيراد من Excel.

### 8.5 عروض الأسعار

- الرأس: الرقم، العميل، الطلب، الخدمة، عنوان المشروع، الموقع، تاريخ الإصدار، صالح حتى، المسؤول.
- البنود: أقسام اختيارية، وصف باللغتين، وحدة، كمية، سعر، إجمالي. إضافة من بنود الأسعار أو كتابة حرة، وترتيب بالسحب.
- الخصم بمبلغ أو نسبة، ثم الضريبة، ثم الإجمالي. الحساب فوري في الصفحة ويُعاد في الخادم عند الحفظ.
- جدول الدفعات من قالب وقابل للتعديل. الشروط من قالب وقابلة للتعديل.
- الحالات: مسودة، مُرسل، مقبول، مرفوض، منتهي. «منتهي» تُحسب من تاريخ الصلاحية.
- الإجراءات: طباعة PDF، إرسال واتساب، تسجيل «مُرسل»، نسخ إلى عرض جديد، إنشاء مراجعة (R1، R2) مع بقاء السابقة للقراءة، قبول وتحويل إلى مشروع، رفض بسبب.
- العرض المقبول يُقفل عن التعديل.
- البحث: الرقم، العميل، عنوان المشروع. الفلاتر: الحالة، الخدمة، المسؤول، نطاق المبلغ، تاريخ الإصدار، ينتهي قريبًا.

### 8.6 المشاريع

- الإنشاء من عرض مقبول (تُنقل البنود والقيمة والدفعات) أو مباشرة.
- الحقول: الرقم، العنوان باللغتين، العميل، العرض، الخدمة، الموقع والإمارة، قيمة العقد، تاريخ البدء، تاريخ الانتهاء المخطط والفعلي، مدير المشروع، فريق العمل، الحالة، الوصف.
- الحالات: لم يبدأ، جارٍ، متوقف، مكتمل، مُسلَّم، ملغى.
- نفس الشاشة للمشروع الطويل والعمل القصير. الفرق في قالب المراحل: العمل القصير مرحلة أو مرحلتان.
- نسبة الإنجاز تُحسب من أوزان المراحل ونسبة إنجاز كل مرحلة.
- صفحة المشروع، ملخص ثابت: الحالة، الإنجاز، الأيام المتبقية أو المتأخرة، قيمة العقد، المفوتر، المحصل، المستحق، التكلفة، الربح.
- التبويبات: نظرة عامة، المراحل، الدفعات، أوامر التغيير، الفواتير والمقبوضات، المصروفات، التقارير اليومية، المستخلصات، المشتريات، العمالة والمعدات، المرفقات، التسليم والضمان، النشاط. كل تبويب يظهر عند بناء وحدته حسب مراحل البناء (القسم 15).
- البحث: الرقم، العنوان، العميل. الفلاتر: الحالة، الخدمة، مدير المشروع، الإمارة، متأخر، نطاق القيمة، تاريخ البدء، تاريخ الانتهاء.

### 8.7 مراحل المشروع

- تُنسخ من قالب الخدمة وتُعدَّل داخل المشروع.
- لكل مرحلة: الاسم، الترتيب، الوزن، البدء والانتهاء المخطط والفعلي، الحالة، نسبة الإنجاز، ملاحظات، صور.
- المرحلة متأخرة إذا تجاوزت تاريخها المخطط ولم تكتمل.
- عرض زمني مبسط يوضح المخطط مقابل الفعلي.

### 8.8 جدول الدفعات

- لكل دفعة: البيان، النسبة أو المبلغ، الاستحقاق بتاريخ أو عند اكتمال مرحلة، الحالة (غير مستحقة، مستحقة، مفوترة، محصلة).
- من الدفعة المستحقة تُنشأ الفاتورة بضغطة واحدة.
- مجموع الدفعات يجب أن يساوي قيمة العقد بعد أوامر التغيير، ويظهر تنبيه عند الفرق.

### 8.9 أوامر التغيير

- أعمال إضافية أو محذوفة بعد التعاقد: الرقم، الوصف، البنود، المبلغ بالموجب أو السالب، الحالة (مقترح، معتمد، مرفوض)، مرفق موافقة العميل.
- الأمر المعتمد يعدّل قيمة العقد ويُضاف كدفعة جديدة.

### 8.10 الفواتير

- فاتورة ضريبية: الرقم، المشروع، العميل، الدفعة أو المستخلص المرتبط، التاريخ، تاريخ الاستحقاق، البنود، الإجمالي قبل الضريبة، الضريبة، الإجمالي.
- الحالات: مسودة، صادرة، محصلة جزئيًا، محصلة، ملغاة. حالات التحصيل تُحسب من سندات القبض.
- بعد الإصدار لا تُعدَّل. تُلغى بسبب وتُصدر بديلة.
- البحث: الرقم، العميل، المشروع. الفلاتر: الحالة، متأخرة، المشروع، العميل، نطاق المبلغ، تاريخ الفاتورة، تاريخ الاستحقاق.

### 8.11 سندات القبض

- الحقول: الرقم، العميل، المشروع، التاريخ، المبلغ، طريقة الدفع، المرجع، تاريخ الشيك، مرفق، ملاحظات.
- توزيع المبلغ على فاتورة أو أكثر، ودفعة مقدمة بدون فاتورة تُسوّى لاحقًا.
- تُلغى بسبب ولا تُحذف.
- الفلاتر: طريقة الدفع، العميل، المشروع، المستلم، نطاق المبلغ، التاريخ.

### 8.12 المصروفات

- الحقول: الرقم، المشروع أو «مصروف عام»، البند، المورد (اختياري)، التاريخ، المبلغ، الضريبة، الإجمالي، طريقة الدفع، من دفع، رقم فاتورة المورد، الوصف، صورة الإيصال.
- إدخال سريع من الموبايل: تصوير الإيصال، المبلغ، البند، المشروع.
- الفلاتر: المشروع، البند، المورد، من أدخل، طريقة الدفع، نطاق المبلغ، التاريخ.

### 8.13 التقارير اليومية للموقع

- تقرير لكل مشروع في اليوم: التاريخ، المهندس، الأعمال المنفذة، المراحل التي تم العمل عليها ونسبة إنجازها الجديدة، عدد العمالة، المعوقات، ملاحظات، صور وفيديو.
- تحديث نسبة المرحلة من التقرير ينعكس على المشروع.
- شاشة موبايل بخطوة واحدة. أيام بدون تقرير تظهر في صفحة المشروع.
- الفلاتر: المشروع، المهندس، فيه معوقات، التاريخ.

### 8.14 المستخلصات

- للمشاريع التي تُفوتر حسب الإنجاز: الرقم، المشروع، الفترة، بنود العقد وأوامر التغيير مع الكمية أو النسبة السابقة والحالية والتراكمية.
- الاستقطاعات: نسبة محتجز الضمان، استرداد الدفعة المقدمة. الصافي المستحق.
- الحالات: مسودة، مُقدَّم، معتمد، مفوتر. المعتمد يُنشئ فاتورة.
- المشروع يعمل بجدول الدفعات أو بالمستخلصات، ويُحدَّد عند إنشائه.

### 8.15 الموردون ومقاولو الباطن

- الحقول: النوع (مورد، مقاول باطن)، الاسم باللغتين، التخصص، الهاتف، البريد، الرقم الضريبي، العنوان، البيانات البنكية.
- صفحة المورد: المشتريات، المدفوع، المستحق، المشاريع.

### 8.16 المشتريات وعقود الباطن

- فاتورة شراء على مشروع: المورد، التاريخ، رقم فاتورة المورد، البنود، الضريبة، الإجمالي، المرفق. المواد تُحمَّل مباشرة على تكلفة المشروع بدون مخزن.
- عقد باطن على مشروع: المقاول، نطاق العمل، القيمة، الدفعات.
- سندات صرف للمورد أو المقاول موزعة على الفواتير، وحالة السداد تُحسب منها.

### 8.17 العمالة والمعدات

- العمال: الاسم، المهنة، اليومية، تابع للشركة أو خارجي، مفعّل.
- حضور يومي لكل مشروع: حاضر، نصف يوم، غائب، ساعات إضافية. يُسجَّل لمجموعة عمال في شاشة واحدة.
- تكلفة العمالة تُحمَّل على المشروع من الحضور. لا توجد رواتب.
- المعدات: الاسم، النوع، مملوكة أو مؤجرة، التكلفة اليومية. تُخصص لمشروع بفترة وتُحمَّل تكلفتها عليه.

### 8.18 التسليم والضمان والصيانة

- التسليم: التاريخ، محضر الاستلام (PDF ومرفق موقّع)، مدة الضمان بالأشهر، وتاريخ انتهاء الضمان محسوب.
- طلبات الصيانة: الرقم، المشروع، التاريخ، الوصف، داخل الضمان أو خارجه، الحالة، المسؤول، التكلفة، الصور.
- الفلاتر: الحالة، المشروع، المسؤول، داخل الضمان، التاريخ.

## 9. لوحة المعلومات والتقارير

### 9.1 لوحة المعلومات

تختلف حسب الدور، وكل رقم فيها رابط للقائمة المفلترة التي أنتجته. فيها فلتر فترة.

- الإدارة: المشاريع الجارية، المتأخرة، إجمالي التعاقدات، المحصل، المستحق، المتأخر تحصيله، ربح الفترة، الطلبات الجديدة، نسبة تحول العروض، والإيراد مقابل التكلفة شهريًا.
- المبيعات: طلباتي، متابعات اليوم والمتأخرة، عروض بانتظار الرد، عروض تنتهي قريبًا.
- المهندس: مشاريعي، معاينات اليوم، مراحل متأخرة، تقارير لم تُرسل.
- المحاسب: دفعات مستحقة، فواتير متأخرة، مقبوضات ومصروفات الفترة.

### 9.2 التقارير

كل تقرير جدول قياسي بفلاتره وتصديره:

- ربحية المشاريع: العقد، المفوتر، المحصل، التكلفة حسب النوع، الربح، الهامش.
- أعمار الذمم: المستحق على كل عميل (حالي، 1–30، 31–60، 61–90، أكثر من 90 يومًا).
- التحصيلات حسب الفترة وطريقة الدفع.
- المصروفات حسب البند والمشروع والفترة.
- ملخص الضريبة: ضريبة المخرجات والمدخلات للفترة.
- أداء المبيعات: الطلبات حسب المصدر والخدمة، العروض حسب الحالة والمسؤول، نسبة التحول.
- المشاريع والمراحل المتأخرة.
- كشف حساب عميل وكشف حساب مورد، مع PDF.

## 10. الربط بالموقع الحالي

- عند إرسال نموذج «اطلب عرض سعر» على الموقع، يرسل الموقع الطلب ومرفقاته إلى النظام عبر API بعد إرسال الرد للزائر، فلا يتأخر عليه.
- الحماية: مفتاح سري في الترويسة، HTTPS، وتحديد لمعدل الطلبات.
- النظام ينشئ طلبًا بمصدر «الموقع» ويحفظ رقم الطلب الأصلي لمنع التكرار، ثم يُشعر المبيعات.
- الموقع يسجل وقت نجاح الإرسال لكل طلب. زر «جلب الطلبات» في النظام يسحب ما لم يصل بسبب خطأ اتصال.
- متابعة الطلب تتم في النظام. قائمة الطلبات في لوحة الموقع تبقى كما هي دون تغيير.
- تعديل الموقع محدود: إجراء الإرسال، عمود `synced_at`، ونقطة جلب الطلبات غير المرسلة.

## 11. الأداء

- صفحات Blade من الخادم. Livewire داخل الجداول فقط، فالتنقل لا يحمّل أكثر من اللازم.
- ملف CSS وملف JS أساسيان، ومكتبات الصفحات الخاصة (الرسوم، الرفع، المحرر) تُحمَّل عند الحاجة فقط.
- خطوط محلية مع `font-display: swap`، ويُحمَّل الخط المختار فقط.
- منع استعلامات N+1 (`preventLazyLoading` خارج الإنتاج) وتحميل العلاقات مسبقًا.
- فهارس على المفاتيح الأجنبية وأعمدة الحالة والتاريخ والرقم وحقول البحث.
- الإجماليات المالية للمشروع تُخزن في أعمدة ملخصة تُحدَّث عند تغيّر مستنداته، فلا تُحسب عند كل عرض.
- تخزين مؤقت للإعدادات والقوائم والصلاحيات والترجمة.
- تصدير Excel متدفق على دفعات.
- الصور تُعرض مصغرة WebP مع تحميل مؤجل.
- هدف القياس: الجدول القياسي بـ 50 ألف سجل يستجيب للبحث والفلترة في أقل من 300 مللي ثانية محليًا.

## 12. الأمان

- تحقق من كل مدخل عبر Form Requests، وتفويض كل إجراء عبر Policies.
- حماية CSRF، وتحديد معدل محاولات الدخول ونقطة الربط.
- الملفات على قرص خاص وتُخدَّم بعد التحقق من الصلاحية. الروابط العامة موقّعة ومؤقتة.
- التحقق من نوع الملف الفعلي لا الامتداد فقط.
- كلمات المرور بطول أدنى وتشفير Laravel الافتراضي. إنهاء الجلسة بعد مدة خمول من الإعدادات.
- لا يُعرض نص غير منقّى بـ `{!! !!}`.

## 13. النسخ الاحتياطي

- نسخة يومية لقاعدة البيانات بمكتبة PHP لا تحتاج أوامر نظام، تعمل عند أول طلب في اليوم بعد إرسال الرد.
- نسخة للملفات المرفوعة يدويًا من الإعدادات.
- عدد النسخ المحتفظ بها من الإعدادات، مع تنزيل النسخة.
- سجل بآخر نسخة ناجحة، وإشعار للمدير عند الفشل.

## 14. الاختبارات والجودة

- اختبارات Feature لكل وحدة: الإضافة والتعديل والحذف والاسترجاع والصلاحيات.
- اختبارات Unit للحسابات: إجماليات العرض والفاتورة، الضريبة، الترقيم، نسبة الإنجاز، ربحية المشروع، توزيع المقبوضات، المستخلص.
- اختبارات للجدول القياسي: البحث، كل نوع فلتر، نطاق التاريخ، الترتيب، التصدير، الحذف الجماعي وحذف الكل.
- اختبار نقطة الربط: مفتاح خاطئ، تكرار، مرفقات.
- بوابة نهاية كل مرحلة: `migrate:fresh --seed` يعمل، Pint نظيف، Larastan نظيف، الاختبارات ناجحة، `npm run build` ناجح، مراجعة يدوية على 390 و 1440 بكسل باللغتين.
- بيانات تجريبية (Seeders) واقعية لكل وحدة لتجربة النظام.

## 16. نقاط تحتاج تأكيد

1. الاستضافة: نفس الاستضافة المشتركة للموقع بدون cron؟ الوثيقة مبنية على ذلك.
2. النطاق الفرعي للنظام: `system.class-skilled.com` أو اسم آخر.
3. الرقم الضريبي للشركة والبيانات البنكية لإدخالها في البيانات الأولية.
